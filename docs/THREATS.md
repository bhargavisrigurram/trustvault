# TrustVault Threat Model & Defensive Mitigations (T01 - T28)

TrustVault implements defense-in-depth mitigations against the 28 threats specified in Section 14 of the engineering challenge. Every threat has at least one dedicated automated test in `tests/security/threat-matrix.test.ts`.

---

| ID | Threat Name | Vulnerability Analysis | Attack Vector / Scenario | Defense Implementation | Verification Test |
|---|---|---|---|---|---|
| **T01** | **IDOR on Document Routes** | Predictable or guessed document IDs accessed by unauthorized users. | User B sends `GET`, `PATCH`, `DELETE`, or `POST` requests targeting User A's document ID. | Central `authorize(user, doc, action)` checks ownership and active grants; returns `404 Not Found` for unpermitted users. | `threat-matrix.test.ts: T01` |
| **T02** | **Direct File URL Guessing** | Files placed under a static public web directory. | Attacker guesses filename under `/storage/files/strategy.pdf` or `/uploads/...`. | Files are stored outside web root with unguessable UUID names; no direct static serving route exists. | `threat-matrix.test.ts: T02` |
| **T03** | **Path Traversal** | Dot-dot-slash (`../`) sequences in filenames or download keys. | Attacker passes `../../etc/passwd` or `..\\..\\windows\\system32` to retrieve server system files. | `StorageService.getFilePath` validates key against strict UUID regex and asserts resolved path starts with storage directory. | `threat-matrix.test.ts: T03` |
| **T04** | **MIME Type Spoofing** | Dangerous binaries disguised with benign extensions (`.pdf`). | Attacker uploads a Windows PE `.exe` or Linux ELF renamed to `contract.pdf`. | `StorageService.validateFileSignature` reads initial buffer magic bytes; rejects PE (`MZ`), ELF (`\x7fELF`), and archives. | `threat-matrix.test.ts: T04` |
| **T05** | **Stored XSS in Filenames** | HTML or JavaScript tags injected into filename metadata. | Attacker uploads `<script>alert(1)</script>.pdf`. | Filename sanitized upon storage; downloads serve `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`. | `threat-matrix.test.ts: T05` |
| **T06** | **Mass Assignment of Roles/Owner** | Overposting attributes like `owner_id` or `role: admin`. | Attacker passes `owner_id: otherId` to `PATCH /api/documents/:id`. | Input schemas validate permitted fields; immutable properties (`owner_id`, `id`) are strictly excluded from update queries. | `threat-matrix.test.ts: T06` |
| **T07** | **Grant Privilege Escalation** | A user with `read` grant attempting mutations. | Grantee attempts `POST /api/documents/:id/versions`, `PATCH`, or `DELETE`. | `authorize(...)` verifies action against grant permission matrix; returns `404` to hide edit capabilities. | `threat-matrix.test.ts: T07` |
| **T08** | **Stale Sessions on Logout / Disable** | Session tokens lingering after logout or deactivation. | User attempts requests using cookie after `POST /api/auth/logout` or after account `is_active = false`. | Sessions are stored server-side and deleted on logout; `authenticate` middleware asserts `user.is_active === true`. | `threat-matrix.test.ts: T08` |
| **T09** | **Download-Token Replay** | Single-use temporary download tokens reused. | Token holder attempts to replay download URL multiple times. | `DownloadTokenService.consumeToken` uses an atomic `UPDATE ... SET is_used = true WHERE is_used = false` query. | `threat-matrix.test.ts: T09` |
| **T10** | **Cross-User / Forged Tokens** | Forged download tokens or tokens from other contexts. | Attacker sends a random or fabricated token to `GET /api/documents/token-download`. | Tokens are cryptographically secure random hex strings mapped to document IDs in the database; unmapped tokens return 401/404. | `threat-matrix.test.ts: T10` |
| **T11** | **Search Metadata Leakage** | Facets or document counts exposing existence of private files. | Attacker views category facet counts or totalCount to infer private document titles. | `getDocumentAuthorizationSqlPredicate()` filters search queries and facet generation at the database SQL query level. | `threat-matrix.test.ts: T11` |
| **T12** | **Downloading Soft-Deleted Documents** | Downloading documents while in trash state. | Owner or grantee requests download of a soft-deleted document. | `authorize(...)` blocks download access on soft-deleted documents until restored; returns 404. | `threat-matrix.test.ts: T12` |
| **T13** | **Accessing Versions without Permission** | Querying version history on unauthorized documents. | Unauthorized user requests `GET /api/documents/:id/versions`. | Versions routes require authorization on the parent document; returns 404 for unpermitted users. | `threat-matrix.test.ts: T13` |
| **T14** | **Audit UPDATE & DELETE Attempts** | Direct modification or tampering with audit log records. | Malicious DBA or injected SQL attempts `UPDATE audit_log` or `DELETE FROM audit_log`. | PostgreSQL trigger `trg_audit_log_immutable` raises an exception on any `UPDATE` or `DELETE`. | `threat-matrix.test.ts: T14` |
| **T15** | **Revocation / Download Race Condition** | Downloading document concurrently as grant is revoked. | Concurrently revoking grant while file download initiates. | Revocation commits immediately; atomic checks guarantee no file streaming starts once revoked. | `threat-matrix.test.ts: T15` |
| **T16** | **Brute-Force Login Attempts** | Automated password guessing against accounts. | Attacker sends multiple failed logins with incorrect passwords. | Failed logins are recorded in audit trail; `AuditService.detectAnomalies()` surfaces brute force activity. | `threat-matrix.test.ts: T16` |
| **T17** | **Verbose Error Leakage** | Server errors leaking database queries, tables, or stack traces. | Sending invalid input to provoke uncaught exceptions. | Central `errorHandler` logs details securely and returns generic sanitized JSON error responses without stack traces. | `threat-matrix.test.ts: T17` |
| **T18** | **CORS Misconfiguration** | Insecure wildcards (`*`) allowing unauthorized cross-origin requests. | Malicious website initiates cross-origin requests to API. | `corsMiddleware` restricts `Access-Control-Allow-Origin` to configured trusted origins with credentials support. | `threat-matrix.test.ts: T18` |
| **T19** | **CSRF Attacks** | Cross-site requests executing state changes using ambient cookies. | Attacker tricks browser into submitting `POST /api/documents`. | Double-submit CSRF cookie/header pattern; state-changing requests without matching `x-csrf-token` return 403. | `threat-matrix.test.ts: T19` |
| **T20** | **Oversized Uploads** | Resource exhaustion via multi-gigabyte upload floods. | Attacker uploads a payload larger than 10MB. | Multer size limits (`fileSize: 10 * 1024 * 1024`) reject oversized streams with HTTP 413 Payload Too Large. | `threat-matrix.test.ts: T20` |
| **T21** | **ZIP / Decompression Bombs** | Highly compressed archives expanding to overwhelm disk/memory. | Attacker uploads a zip bomb disguised as a valid document. | Magic byte inspection strictly forbids `application/zip` and archive headers; files are never extracted on the server. | `threat-matrix.test.ts: T21` |
| **T22** | **Concurrent Edit Collision** | Simultaneous updates overwriting each other silently. | Two editors submit version 2 concurrently. | Optimistic Concurrency Control checks `expectedVersion === current_version_number`; conflicts return 409. | `threat-matrix.test.ts: T22` |
| **T23** | **Storage Failures & Orphaned Objects** | Unlinked files left on disk after database rollback. | Network drops during document creation. | Uploads stage to temp folder; committed to storage inside transactional boundaries with cleanup hooks. | `threat-matrix.test.ts: T23` |
| **T24** | **Audit-Write Failures & Broken Chaining** | Tampered audit hashes or interrupted sequences. | An entry is modified or deleted in the database. | SHA-256 hash chaining ensures `verifyChain()` detects any altered payload or missing sequence number. | `threat-matrix.test.ts: T24` |
| **T25** | **Session Fixation** | Attacker pre-sets a session cookie before authentication. | Attacker passes pre-existing session ID before login. | Session identifier is regenerated upon successful login; pre-login session is discarded. | `threat-matrix.test.ts: T25` |
| **T26** | **Disabled-User Access** | Deactivated users maintaining active access. | User account set to `is_active = false`. | Authentication middleware rejects credentials with 403 `ACCOUNT_DISABLED`; active sessions immediately denied. | `threat-matrix.test.ts: T26` |
| **T27** | **Expired Grants** | Accessing shared documents past the grant expiration timestamp. | User accesses document after `expires_at` has passed. | Central authorization engine checks `expires_at > NOW()`; expired grants are treated as non-existent (404). | `threat-matrix.test.ts: T27` |
| **T28** | **Admin Document Access without Grant** | Privileged admin inspecting private documents. | System admin attempts `GET /api/documents/:id/download`. | Least privilege: Admin has no implicit document content access; returns 404 Not Found without explicit grant. | `threat-matrix.test.ts: T28` |

## 2. Mutation Testing

TrustVault includes an automated mutation test harness in `scripts/mutation-test.ts` (`npm run mutation-test`).

The harness verifies that:
1. Mutating the central authorization function to unconditionally grant access (`return { allowed: true }`) causes the test suite to **fail**.
2. Bypassing authorization in the download streaming service causes the test suite to **fail**.
3. Bypassing authorization in the metadata retrieval service causes the test suite to **fail**.
4. All source files are restored to their original pristine state after testing.
